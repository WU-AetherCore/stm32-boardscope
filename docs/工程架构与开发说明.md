## 串口数据流

RX：UART → 循环 DMA 的 100 字节缓冲 → HT/TC/IDLE 回调 → 新增字节记录与复制队列 → 通信任务中解析协议。
TX：业务调用 Board_Send → 复制到固定队列 → 空闲时启动 DMA → HAL 完成回调记录字节并释放活动缓冲。

每路 TX/RX 队列各 8 槽，保留一槽判满，有效容量各 7 包，每包最多 128 字节。队列满会累计计数，不覆盖待处理包。
发送入队成功不等于完成；完成统计也不等于对端应用确认。发送缓冲区受所有权保护，DMA 完成前不覆盖。
正常 128 字节在 115200bps 下约 12ms；超过 500ms 未完成时终止该发送并累计失败。
回显默认关闭，避免与对端回显形成无限循环；UI 可逐路启用。清除历史只清除 RX/TX 浏览记录，不清零累计统计。

UART1 使用 CR/LF 分隔调试指令，支持跨 DMA 分片和一包多行；非法/超长命令返回 ERR，严格拒绝额外参数。
UART2 保留 Fa0–Fa9 的继电器控制和 FbA/FbB 的旧状态协议，并允许三字节命令跨 DMA 分片。
若接收队列丢包，UART1 放弃当前未完成的行，直到下个分隔符再同步，防止拼接损坏命令。
串口错误中断只标记恢复请求；下一轮任务中重启接收，不在 IRQ 中阻塞或执行 UI。

这是监测与调试模块，不承诺在全部六路持续满速、OLED 大量刷新时零丢包。通信统计提供丢包和错误计数用于评估。

## 内存指标口径

照片中的 FLASH/RAM/CCMRAM 和 text/data/bss 是当前固件的链接结果：程序运行期间保持不变，每次编译会更新。
链接脚本生成 `__board_*` 绝对符号，固件取得符号值；没有把照片的旧数字写死。
`tools/verify_memory.py` 对 Debug/Release 的符号与 GNU size 输出作严格比较。

- FLASH 已用：链接器分配给 FLASH 的跨度，包括初始化数据的装载镜像与对齐。
- RAM 静态：.data、.bss、链接预留堆/栈以及对齐；FreeRTOS 堆数组已包含在 .bss。
- CCMRAM：当前映射的 CCM 区段占用，不代表 DMA 可用存储。
- text/data/bss/dec/hex：GNU size 的同口径分类；构造/析构数组按可写段归入 data，dec 为三者之和，hex 是 dec 的十六进制。
- 实时堆：FreeRTOS 堆总量、当前空闲、当前已用、历史最小空闲，每 250ms 查询。
- 栈余量：各任务从启动以来的最小剩余栈，FreeRTOS 返回 words，界面转换为字节。

不能把“RAM 静态已用”再加上“实时堆已用”，否则会重复计算。页中的栈值不是当前 SP，也不是全板物理 RAM 的瞬时总使用量。
新增内存状态页入口：首页“内存状态”，或设备状态 → 内存状态。旋转滚动、按下返回。

## 新增功能

1. 在 BoardApp/src 或 Drivers/WU 下新增 .c，CMake 自动加入；新增 include 目录需同步 target_include_directories。
2. UART 业务调用 Board_Send(port,data,size)，port 为 0..5；超长内容由调用方分段，明确处理 false 返回。
3. 添加 UI 行时扩展固定文本数组和路由/页面计数；避免在回调中直接绘制。
4. 三个普通按键业务在独立文件实现 Board_OnKeyEvent，事件编号见 board.h，回调应快速返回。
5. CubeMX 再生成 USART 时检查六路 RX DMA 是否仍为 Circular；Core 修改点与生成配置需要一起维护。

## 构建和检查

MCU 工程仍使用 Debug/Release presets。桌面测试使用 `tests/CMakeLists.txt`，必须选桌面 GCC，而非 ARM GCC。

```powershell
cmake -S tests -B build/HostTests -G Ninja -DCMAKE_C_COMPILER=桌面gcc.exe的绝对路径
cmake --build build/HostTests
ctest --test-dir build/HostTests --output-on-failure
python tools/verify_memory.py
```

测试涵盖：发送复制/完成计数、队列满、DMA 回绕/重复位置、跨包 STATUS、非法尾随参数、UART2 兼容命令、发送超时、接收恢复和历史边界。
测试使用真实串口管理源文件及模拟 HAL，不能代替实际串口接线、DMA IRQ 和外设对端验收。
开源副本仅包含可复现构建需要的源码、许可证、说明与验证摘要；本机备份不随仓库发布。
协议测试还覆盖完整快照、缺行、顺序、重复串口编号、非法 JSON、重启序号和最大行长度。
